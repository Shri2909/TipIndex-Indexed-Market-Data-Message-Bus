## PY-01 — Independent trace parser allocates from unchecked record count

**Medium; confirmed (before correction).** `py/tiplog_py/exp/oracle.py:55-108` (`dictionary` / `TraceIndex.__init__`). A 68-byte malformed trace declaring 10,000 records reaches `open_memmap(shape=(count,))` before establishing that those records can fit in its record region. The executed probe created a 260,192-byte `.partial.npy` and then raised `struct.error`; count scales directly with a forged u64. Larger counts can consume address space or sparse-file quota even though the input contains no records. Constructor failures also leave its input mapping/stream and temporary cache unmanaged. Dictionary bounds/duplicate-path validation is incomplete relative to the trace contract.

Evidence: `evidence/python/initial-probes.json`, `impossible_record_count`. Root cause: allocation precedes physical record-count validation, and construction has no failure cleanup. Correction: independently validate header/dictionary/count bounds first; reserve unique owned cache staging; remove failed staging and close partially initialized resources; reject duplicate dictionary paths. Compatibility: accepted traces/cache schema remain unchanged. Required validation: malformed counts/regions/dictionaries reject before allocation; malformed records and injected publication failures leave no staging; valid caches reuse identically. Status: **fixed and verified**; final verification is recorded below.

## PY-02 — Trace writer context manager leaks staging after failed finish

**Low; confirmed (before correction).** `py/tiplog_py/trace/format.py:97-125` (`finish`, `abort`, `__exit__`). A publication `OSError` during normal context exit leaves the uniquely owned `.partial` behind and `closed=False`. Repeated failed conversions through the public writer API can accumulate full-sized traces; the CLI's outer abort happens to mitigate its own callers. Probe preserves the old destination but confirms the abandoned staging file.

Evidence: `evidence/python/initial-probes.json`, `writer_failure`. Correction: make `finish` abort its owned staging on every handled failure and ensure `abort` unlinks in a `finally` block. Compatibility: successful bytes and original exception propagation stay unchanged. Required validation: failing write/close/rename paths clean staging and preserve old destination; success remains readable. Status: **fixed and verified**; final verification is recorded below.

## PY-03 — Quiescence checker treats absent sampling as zero CPU interference

**Medium; confirmed (before correction).** `scripts/check_p7_runtime_quiescence.py:47-67,89-102` (`foreign_cpu23_seconds`, `audit_campaign`). An empty or singleton process audit returns `(0.0,{})`, so a correctly hash-bound but empty accepted artifact satisfies the maximum-foreign-CPU rule. A decreasing tick counter yields negative foreign CPU (-10 seconds in the probe), which also satisfies the rule and can offset real interference. Hash binding proves file identity, not sufficient observations or valid counters.

Evidence: `evidence/python/initial-probes.json`, `quiescence_empty`, `quiescence_singleton`, `quiescence_regressing`. Correction: require at least two nonempty process snapshots, unique valid process identities/counters and nondecreasing per-process CPU; validate finite positive tick rate, chronological samples and idle fractions; report invalid sampling as a failed round. Preserve the declared consecutive-snapshot metric and its documented sampling limitations. Required validation: whole-campaign empty/singleton/regressing negative controls fail even with consistent hashes; valid quiet/noisy controls and frozen accepted evidence remain correctly classified. Status: **fixed and verified**; final verification is recorded below.

## PY-04 — Analysis write sets can destroy their own input or summary

**Medium; confirmed (before correction).** `py/tiplog_py/analysis/summarize.py:324-366` (`build` / `write_tables`) and `py/tiplog_py/layout/analyze.py:583-633` (`build` / `main`). P6 analysis permits its summary or any fixed CSV destination to alias append-only input JSONL; `build(raw, raw)` successfully replaces the original observations. A summary named `tip-statistics.csv` is first written as JSON then replaced by its own CSV output. Layout analysis opens `--csv` with truncation before reading its inputs, so a CSV/input alias destroys those rows; summary/metadata/output collisions are similarly unguarded. Existing CLI conversion source-preservation fixes do not cover these analysis APIs.

Evidence: `evidence/python/analysis-output-probe.json` records source replacement and self-overwritten summary. Root cause: outputs are independently opened without full write-set/source checks or staged bundle publication. Correction: reuse owned output transactions with multiple protected input paths; validate all derived destinations before writes, include metadata/global/used frequency sidecars, stage tables/summary before publication and roll back handled publication failures. Compatibility: normal output bytes/locations and explicit failed-analysis diagnostics remain unchanged; destructive aliases now raise. Required validation: direct/symlink/hardlink aliases and output collisions preserve raw inputs; injected table/publication failures preserve old bundles; existing analysis/figure suites pass. Status: **fixed and verified**; final verification is recorded below.

## PY-05 — Retention oracle accepts negative sizes and silently wraps logical sums

**Low; confirmed (before correction).** `py/tiplog_py/exp/oracle.py:174-211` (`retained_layout`, original snapshot line 121 onward). Signed negative values pass the oversized-record test, then convert to u64. For `[-1]` the PAD loop repeats the same crossing indefinitely; the bounded probe intercepts the first nine identical searches instead of exhausting memory. Separately, `[2**63, 2**63]` at capacity `2**63` silently wraps the u64 prefix sum and reports `head_pos=0` after two records. Production trace/synthetic sizes are positive and small, so this does not invalidate the frozen real campaigns.

Evidence: `evidence/python/retention-input-probe.json`. Correction: require one-dimensional positive integer sizes and a representable power-of-two capacity; reject overflowing cumulative DATA/PAD positions before u64 arithmetic. Preserve all existing positive-size retention semantics. Required validation: negative/zero/noninteger inputs reject without PAD searches; DATA and PAD overflow reject; scalar queue differential and existing scaling regressions still pass. Status: **fixed and verified**; final verification is recorded below.

Peer review found an additional representable-domain boundary before its correction: `sizes=[2**62,1,2**62,1]`, `capacity=2**63` incorrectly retains sequence 2 at position `2**62`, below cutoff `2**62+1`. Its correct retained boundary is the PAD at `2**62+1`, sequence floor 3. NumPy promotes an untyped Python search key with the uint64 array and rounds the cutoff. Evidence: `evidence/python/retention-scalar-key-probe.json`. Both PAD crossing and retained-floor searches will use explicitly checked uint64 scalar keys; independent scalar comparisons near integer precision boundaries are required. This is included in PY-05 because it shares the unchecked NumPy integer-representation boundary and correction.
