No external implementation code was copied. Aeron source-code implementation was not inspected or reused; wiki is documentation without a source-code revision. Kafka is moving `trunk` documentation, not a pinned implementation reference. Jane Street's published scan/hierarchy/event-order statements are preserved as published statements; the ring layout, progress/checkpoint algorithm and independent test campaign are this project's design, not an Aria reconstruction. No kernel, index, concurrency, durability or P6 experiment is introduced here.

Campaign capacities are 4/8/16/32/64 KiB with seeded random paths (roots, two-segment partitions, internal topics and leaves), later topics, overlapping/nonexistent/wide terms, invalid empty spec rejection, payload lengths including zero/max/oversized, eight interleaved snapshots, captured uppers and paused consumption. Each publication compares independently derived head/tail positions/sequences. After every operation the engine checks invariants. Every batch compares exact status/error/checkpoint/upper and copied-or-immediately-compared seq/pos/raw path/payload. `fell_behind_batches` counts batch calls in that error state, including stable terminal re-reads; it does not claim distinct failed cursors.

A review of explicit resume checkpoints added one boundary proof beyond the sequence-only campaign: C=64, payloads 10/4/8/0 leave `head=104, tail=56(PAD), tail_seq=3`. A valid supplied `{after_seq=2,next_pos=56}` must retain that PAD even though preceding DATA seq2 was evicted. The engine proves it using the known tail boundary, `after+1==tail_seq`, PAD type and exact end at canonical next-DATA seek; arbitrary aligned offsets still fall back safely. `V36RetainedTailPadCheckpointSurvivesPrecedingDataExpiry` then evicts only that PAD and checks the conservative FellBehind outcome. This is the approved checkpoint contract applied to a newly explicit test, not a scope amendment.
