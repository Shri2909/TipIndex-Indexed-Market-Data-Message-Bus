## Material corrections before coding

| Finding in v1.0 | v1.1 resolution | Future evidence |
|---|---|---|
| Scan can expire on unrelated records while indexed replay succeeds, contradicting mode equivalence | Shared conservative unread checkpoint and batch-status rules | V35 plus existing differential checks |
| Last delivered sequence is not the same as completed-range progress | Snapshot completion advances a separate bookmark, including zero-output ranges; future-start tail behavior is explicit | V35 |
| A PAD plus a large record can exceed ring capacity | max_record≤C/2, checked arithmetic and rejection before mutation | V36 |
| Late delta-overflow seals invalidate global FIFO ordering | Sealed-block expiry min-heap; complexity/memory costs updated | V37 and M2/T5 |
| Four-byte entries were treated too much like total index cost | Include stale entries, open/sealed slack, heap/list storage and generic minimum DATA16 vs ITCH32 | V17/V19/V37 and T5 |
| Packed positions/ids can overflow or collide with sentinel | Checked bounded lifetime/ids, reserved sentinel and explicit limits | V38 |
| Atomic reader loads were described as a sufficient concurrency protocol | Withdraw unproved fence recipe; require complete writer/reader/lifetime/reclamation justification in R4 | Later R4 review and checks |
| Fractional cost inputs and partial windows overstated exactness | Scaled rational full-window model, checked intermediates, independent DP bound and exact-coverage limits | V39, DP/ENUM checks in P7 |
| Plateau endpoint and global budget certificates were overbroad | Finite threshold domain, nonnegative multiplier and exact/certified per-partition terms required | V39 and coverage report |
| Gzip ISIZE was reduced to two possible full sizes | Exact full-stream size remains unknown until checked streaming count | P1 |
| perf level/cache eviction/restart were treated as stronger guarantees | Successful PMU probes, named cache treatments/residency snapshots, and explicit storage-failure model | P0/P6; later R1/R3 |
| Yesterday's environment was treated as a current dependency pin | New dated metadata; explicit validated interpreter/venv and compatible pins in P0 | P0 |

The optimizer's **class-mask state is retained**. The review supports its full-window multiplier-mask argument; the earlier objection to a scalar store-count-only DP does not invalidate this richer recurrence. No optimizer has been executed, so this is analytical review, not an implementation correctness result.
